1. OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
The Eve Vakh login portal provides a dual-mode authentication architecture:
  A. One-Time Password (OTP) Flow: Default mode that requests a one-time verification
     code sent to the user's email address or phone number.
  B. Password Authentication Flow: Direct credential login using a registered email
     and secret password.

Backend Communication:
  - Authentication Endpoint: POST https://xo.eve.vakh.com/api/auth/sign-in/email
  - Session Bootstrap     : GET  https://xo.eve.vakh.com/api/profiles/ensure
  - Feed Initialization   : GET  https://xo.eve.vakh.com/api/init/feed
  - Final Redirection     : https://eve.vakh.com/ (Home / Dashboard)

2. DETAILED BUTTON & COMPONENT SPECIFICATIONS
--------------------------------------------------------------------------------

[1] "web" Link (Landing Page Navigation)
----------------------------------------
- Location     : Top-right navigation area on the homepage (https://eve.vakh.com/)
- Locator      : a[href*="/auth/sign-in"] OR getByRole('link', { name: /^web$/i })
- Use          : Acts as the primary gateway for web visitors to navigate from the
                 public marketing landing page to the application sign-in route.
- Working      : Clicking this element triggers client-side routing directly to
                 https://eve.vakh.com/auth/sign-in without a full document reload.
- Test Status  : Verified and passing across 4 browser engines in ~4.5 seconds.


[2] "Email or phone number" Input Field
----------------------------------------
- Location     : Top text box in the central login form card.
- Locator      : getByPlaceholder(/email or phone number/i) OR
                 locator('input[autocomplete="username"]')
- Attributes   : type="text", autocomplete="username", placeholder="Email or phone number"
- Use          : Captures the user's identity (email address or registered mobile number).
                 Example test account: mughdabansal2094@gmail.com.
- Working      : Listens for input events, validates user string input in real time,
                 and updates the form component state to enable the primary action button.


[3] "Use password" Link Button
----------------------------------------
- Location     : Text link button placed directly underneath the main action button
                 ("Send code").
- Locator      : getByRole('link', { name: /use\s*password/i }) OR
                 getByText(/use\s*password/i)
- Attributes   : role="link", aria-label="Use password"
- Use          : Toggles the authentication mode from OTP code dispatch to
                 traditional password-based login.
- Working      : When clicked, it dispatches an internal state toggle:
                   1. Unhides the "Password" input field.
                   2. Transforms the primary submit button from "Send code" to "Sign in".
                   3. Displays an alternative toggle: "Use a one-time code instead".
- Test Flow    : Automated test clicks this button before filling the email and password.


[4] "Password" Input Field
----------------------------------------
- Location     : Directly beneath the email field (visible after clicking "Use password").
- Locator      : getByPlaceholder(/password/i) OR locator('input[type="password"]')
- Attributes   : type="password", autocomplete="current-password", placeholder="Password"
- Use          : Secure entry of account password credentials (e.g. M@12345678).
- Working      : Obscures typed characters by default. Dispatches change/input events
                 that validate password requirements and enable the "Sign in" button.


[5] "Show password" Eye Toggle Button
----------------------------------------
- Location     : Embedded icon button at the trailing edge of the password input box.
- Locator      : getByRole('button', { name: /show password/i })
- Attributes   : role="button", aria-label="Show password"
- Use          : Permits the user to temporarily unmask and inspect their entered password
                 to correct typing mistakes.
- Working      : Clicking toggles the input field's DOM type attribute between
                 'password' (masked) and 'text' (plain text).


[6] "Sign in" Button
----------------------------------------
- Location     : Primary action button inside the card in password authentication mode.
- Locator      : getByRole('button', { name: /sign in/i })
- Attributes   : role="button", type="button", text="Sign in"
- Use          : Submits the user's email and password to authenticate the session.
- Working      : 
    1. Validates presence of email and password in form state.
    2. Issues HTTP POST request to https://xo.eve.vakh.com/api/auth/sign-in/email.
    3. Server verifies bcrypt password hash and issues an Ed25519 JWT session token.
    4. Client establishes secure cookies and fetches initial profile data.
    5. Navigates the browser to the authenticated home page at https://eve.vakh.com/.
- Test Status  : Verified with automated redirection assertion in 5–7 seconds.


[7] "Send code" Button (OTP Mode)
----------------------------------------
- Location     : Primary colored button displayed in default OTP mode.
- Locator      : getByRole('button', { name: /send code/i })
- Attributes   : role="button", type="button", text="Send code"
- Use          : Requests a 6-digit one-time login verification code sent to the email
                 or mobile number provided.
- Working      : Sends a POST request to initiate OTP dispatch. Upon 200 OK response,
                 renders the verification code input field and continue button.


[8] "Use a one-time code instead" Link Button
----------------------------------------------
- Location     : Positioned beneath the "Sign in" button in password mode.
- Locator      : getByRole('link', { name: /use a one-time code instead/i })
- Attributes   : role="link", aria-label="Use a one-time code instead"
- Use          : Allows users who forgot their password to switch back to email OTP mode.
- Working      : Re-renders the form into OTP mode, hiding the password input field
                 and restoring the "Send code" button.


[9] "Recovery" Button
----------------------------------------

- Locator      : getByRole('button', { name: /recovery/i })
- Attributes   : role="button", aria-label="Recovery"
- Use          : Account recovery assistance for locked accounts or lost credentials.
- Working      : Opens the recovery modal offering self-service identity recovery steps.


[10] "About" Button

[11] "More" (Show more actions) Button

- Attributes   : role="button", aria-label="Show more actions"
